Pixel reveal uses `resolving-image.html` for project cards, heroes, and case-study media. The same controller also handles every video within the portfolio shell. Alternative text and real image sources remain native HTML; JavaScript failure leaves standard image loading intact. GIFs use a static first-frame preview and return to the original animated image after decode.

Adjust all animation parameters in the `settings` object in `source/js/pixel-reveal.js`: 600 ms total and eight pixel sizes `[100, 64, 40, 24, 12, 6, 2, 0]`. Each stage lasts 75 ms; zero switches to the native, full-resolution image for the last stage. A preview stays coarse until the original decodes and the visibility trigger has been reached, including for cached images. `settings.visibilityThreshold` defaults to 0.25: IntersectionObserver starts the reveal when a quarter of the media element is visible. For elements whose maximum viewport-visible area is less than a quarter of their total area, the trigger is a quarter of that attainable area. Thresholds are recalculated on viewport resize and observer updates. Loading and decoding remain independent of the trigger; no image requests wait for it. Crossing the threshold is remembered if decode is still pending. Once triggered and decoded, the sequence runs to completion even when scrolled out of view. Offscreen decoding alone does not consume the animation. A completed image never replays during the current document session. Each media element tracks its own reveal. Reduced motion skips the sequence once the original is ready. Temporary canvases are removed on completion, failure, or page exit. Native lazy loading remains responsible for full-image requests.

Initial viewport rule: after `pageshow`, two animation frames allow layout and restored scroll positions to settle before observer snapshots classify media. Fully visible media follows the normal reveal; initially partial media stays coarse until a real scroll-position change, then uses the normal 25% threshold. `settings.visibilityTolerance` allows 1 CSS pixel of clipping without classifying a fully visible element as partial. Scroll baselines include the window and media ancestors, so horizontal project-browser scrolling also unlocks pending media; wheel/touch intent and unchanged scroll events do not. Only the first real scroll refreshes the pending set when IntersectionObserver is available. Loading, decoding, and reduced motion remain independent. Back-forward-cache restores reclassify pending elements against the restored viewport, retaining completed and already-triggered states.


Videos use a lightweight poster preview or generated first-frame preview while waiting. Authored posters remain intact; generated placeholder posters are removed when a decoded video frame becomes available. The reveal samples a playing video only at the seven pixelated stages and then removes its canvas. It never calls play/pause/load, seeks, or changes autoplay, loop, muted, or controls settings. Paused videos can resolve their authored poster without forcing playback. Native controls remain visible and interactive beneath an uncovered control strip. Videos outside the shared templates fall back to an existing poster or their first available decoded frame. If neither is available, native video loading remains visible until a frame arrives.

After changing project images or videos, run `ruby script/generate_image_previews.rb` on macOS (uses built-in `sips` for images and `ffmpeg`/`ffprobe` for videos), then commit the generated `source/_data/image_previews.json` with the images. SHA256 checks avoid rebuilding unchanged previews. GitHub Pages needs no custom plugin. Missing preview metadata gracefully falls back to a standard image. Previews are embedded in HTML, adding a few KB per image but requiring no preview network requests. Width/height metadata reserves the original aspect ratio; existing featured-card cropping stays in CSS.

Validation: `ruby script/validate_portfolio.rb`, `bundle exec jekyll build`, `node --check source/js/pixel-reveal.js`, `node script/test_pixel_reveal.cjs`, and Sass compilation. Browser review should include desktop/mobile, throttled network, cache reload, scrolling, category filtering, return navigation, reduced motion, and failed requests.

Verified in isolated headless Chrome at desktop and mobile sizes: homepage image cards, case-study images, playing videos with authored posters, and videos with generated frame previews. Slow incremental scrolling stayed coarse at 10% and 24% visibility and revealed above 25%; rapid scrolling away completed the sequence, returning did not replay it, and playing videos continued. The homepage currently contains image cards only (no video cards). Unit checks additionally cover cached media, oversized elements, delayed decode, reduced motion, paused posters, missing previews, and errors.
